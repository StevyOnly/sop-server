SOP 后端 API 接口文档

基于 internal/router、internal/api、internal/service 与 internal/model 当前实现的全量梳理（共 63 个业务接口）。

基础信息

  • 基础路径：/api/v1（健康检查与静态资源在根路径下，不属于 API 前缀）
  • 数据格式：JSON（例外：base/login 兼容 multipart/form-data；media/uploadMedia 为 multipart/form-data）
  • 认证方式：JWT Bearer Token，请求头 Authorization: Bearer <token>
    • 除 GET /health、POST /base/login、POST /base/appLogin 与 /uploads/* 静态资源外，其余接口均需认证
    • JWTAuth 中间件同时兼容两类令牌：Web 登录签发的普通 JWT（有效期由配置决定）与 APP 端 appLogin 签发的永久 AppToken（Claims.Type = "app"）
    • 多数写接口额外挂载 RequireActiveUser()：按登录态反查 Onebe 用户信息，要求 status == 1（启用）才放行，否则返回 403
  • 数据库：SQL Server（GORM），三库：SOPHub（业务主库，读写）、Onebe（点检/维修老库，只读）、Sparepart（备件库，只读）
  • 时间格式：LocalTime 统一输出 YYYY-MM-DD HH:mm:ss，零值输出空串 ""
  • URL 改写：挂载 ResourceURL() 的接口，出参将 /uploads/... 相对路径替换为完整 URL；入参将 http(s)://host/uploads/... 绝对地址剥回相对路径后入库（幂等）

通用响应格式

统一响应信封

所有业务接口（除 /health 与 Excel 导出）均返回统一信封：

{
  "code": 0,
  "data": {},
  "msg": "操作成功"
}
  • 成功：code = 0（HTTP 200），data 为各接口说明的业务数据
  • 无返回数据的成功响应（更新/删除类），data 固定为空对象 {}
  • 业务失败（HTTP 状态码与业务码一致，data 为 null）：
{ "code": 404, "data": null, "msg": "指南不存在" }

业务错误码

code / HTTP说明
0成功（HTTP 200）
7通用失败（HTTP 200）。参数绑定失败统一返回泛化提示「请求参数错误」（真实原因仅记服务端日志，不泄露校验器内部细节）；未知错误返回「服务器内部错误」
400参数错误（业务校验失败，如「回复内容不能为空」「单个指南步骤数量不能超过 100」）
401未认证 / 认证失败（token 缺失、过期、无效；appLogin 的 appKey 不匹配）
403无权限（如用户已被禁用）
404资源不存在
409冲突（如菜单名称已存在、指南/执行说明选项已被引用、备件已配置属性）
500服务器内部错误（code=7，未知错误回退，原始错误仅记服务端日志）

分页信封

分页列表接口的 data 统一为如下结构（下文以「分页信封」指代，仅 data.list 项结构因接口而异）：

字段类型说明
listarray当前页数据列表，项结构见各接口「响应数据」表
totalint64符合条件的总条数
pageint当前页码
pageSizeint当前页大小（请求中的 limit / pageSize 映射到此字段返回）
paginationobject冗余分页对象：page / limit / total，与上面三个字段一致
 
{
  "code": 0,
  "data": {
    "list": [],
    "total": 0,
    "page": 1,
    "pageSize": 10,
    "pagination": { "page": 1, "limit": 10, "total": 0 }
  },
  "msg": "操作成功"
}
分页参数归一化：page <= 0 取 1；limit/pageSize 缺省取 10，最大 100（各列表接口统一）。仅 Excel 导出接口内部以 pageSize=100000 拉取全量。

通用基础字段（BaseModel）

多数 SOPHub 表的响应对象都包含以下字段（由 model.BaseModel 提供），下文各响应表中以「（BaseModel）」简写引用：

字段类型说明
iduint主键
createTimestring创建时间（YYYY-MM-DD HH:mm:ss，自动填充）
updateTimestring更新时间（YYYY-MM-DD HH:mm:ss，自动填充）

权限与中间件图例

各接口标题下方以徽章标注该接口挂载的中间件：

徽章中间件说明
免认证-无需携带 token
需登录JWTAuth()校验 Bearer Token，兼容普通 JWT 与永久 AppToken；失败 401
需启用用户RequireActiveUser()反查 Onebe 确认用户存在且 status=1（启用）；明确不存在/禁用时 403，Onebe 基础设施故障时放行
multipart-请求体为 multipart/form-data（文件上传）
免超时NoTimeout()豁免服务器级读/写超时（大文件上传）
URL 改写ResourceURL()出参相对路径补全为完整 URL，入参绝对地址剥回相对路径
批量 ID 类接口约定：请求字段 ids 校验 required,min=1,max=1000（上限对齐 SQL Server 单条语句参数约 2100）；user/getUsersByIDs 是唯一未限制数量的批量接口（服务端按 1000 一批分片查询）。

1. 基础模块 /base

1.1 用户登录 — POST /base/login

POST免认证

支持 application/json 与 multipart/form-data 两种请求体；两种格式下字段名均为 name / password。bcrypt 校验密码，「用户不存在」伪装成「用户名或密码错误」（防枚举）。

请求参数

字段类型必填说明
namestring是用户名
passwordstring是密码
测试模式下（配置 server.skipPasswordCheck = true）跳过密码校验，任意密码均可登录。用户 info 缺失或 status != 1 时返回 403「用户已被禁用」。
{
  "name": "admin",
  "password": "123456"
}

响应数据

字段类型说明
userobject用户登录记录（nxp_user，password 不返回）
user.iduint用户主键（= JWT UserID）
user.userIdint业务用户 ID
user.namestring用户名
user.createTimestring创建时间（YYYY-MM-DD HH:mm:ss）
tokenstringJWT 令牌，后续请求作为 Bearer Token 携带
expire_atint64令牌过期时间戳（毫秒级）
 
{
  "code": 0,
  "data": {
    "user": {
      "id": 1,
      "userId": 1,
      "name": "admin",
      "createTime": "2026-01-01 00:00:00"

    "token": "<jwt>",
    "expire_at": 1760000000000

  "msg": "登录成功"
}

1.2 APP 端免密码登录 — POST /base/appLogin

POST免认证

仅支持 JSON 请求体。APP 端以固定 appKey（配置 server.appTokenKey）换取永久 AppToken，与用户密码无关。appKey 采用恒定时间比较；反查 Onebe 确认用户存在且启用（禁用/幽灵账号拒绝签发）。

请求参数

字段类型必填说明
userIduint是用户 ID（nxp_user.id）
appKeystring是APP 固定密钥，不匹配返回 401
 
{
  "userId": 3,
  "appKey": "your-app-key"
}

响应数据

字段类型说明
userobject用户登录记录，子字段同 1.1（id / userId / name / createTime）
tokenstring永久 AppToken（Claims.Type = "app"，有效期约 100 年近似永久，可通过更换 appKey 全局吊销），验签路径与普通 JWT 一致，可直接访问其余需认证接口
expire_atint64固定返回 0 作占位（token 不设实际过期）
 
{
  "code": 0,
  "data": {
    "user": { "id": 3, "userId": 3, "name": "zhangsan", "createTime": "2026-01-01 00:00:00" },
    "token": "<app-token>",
    "expire_at": 0
  },
  "msg": "登录成功"
}
