SOP APP 端 API 接口文档

面向 PDA / APP 端的接口子集（共 31 个），基于 app.md 与 internal/api、internal/service 当前实现整理；完整接口（含 Web 管理端）见 api.html。

基础信息

  • 基础路径：/api/v1（健康检查与静态资源在根路径下，不属于 API 前缀）
  • 数据格式：JSON（例外：media/uploadMedia 为 multipart/form-data）
  • 认证方式：APP 永久 AppToken（由 appLogin 签发，载荷 type = "app"），请求头 Authorization: Bearer <token>，APP 端全部接口统一使用它鉴权（详见认证说明）
  • 两层鉴权：
    • JWTAuth：仅校验 token 签名与有效期（不查库），失败 401；已签发 token 在有效期内不重复查库校验用户状态
    • RequireActiveUser：仅用于写类操作（reply / upload / save 等），在 JWTAuth 之后反查 Onebe 确认用户存在且启用；Onebe 不可用/超时（基础设施错误）时放行，此时后端取用户名等逻辑回退为前端传入值
  • 数据库：SQL Server（GORM），三库：SOPHub（新库，读写，全部 nxp_sop_* 业务表）、Onebe（老库，只读：用户/设备/机型/点检字典）、Sparepart（备件老库，只读）
  • 时间格式：LocalTime 统一输出 YYYY-MM-DD HH:mm:ss，零值输出空串 ""（老库个别表时间为 unix 秒，见各接口说明）
  • URL 改写：挂载 ResourceURL() 的接口，出参将 /uploads/... 相对路径替换为完整 URL；入参将绝对地址剥回相对路径后入库（幂等）

认证说明

除 POST /base/appLogin 与 GET /health 外，所有接口的 token 都必须加在请求 Header 中：

参数名类型必填描述
Authorizationstring是Bearer <token>（Bearer 与 token 之间一个空格），token 为 appLogin 返回的 data.token
 
Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.<payload>.<signature>
未携带或格式错误将返回 401（{"code":401,"msg":"未提供认证信息"} / {"code":401,"msg":"认证格式错误"}）。token 为 HMAC-SHA256 签名 JWT，载荷含 userId（= nxp_user.id）、签发时间、过期时间、issuer = "sop"；AppToken 无自然过期，仅当服务端更换 server.appTokenKey 时全局失效，需重新 appLogin。

通用响应格式

统一响应信封

所有接口均返回统一信封 { code, data, msg }：

{
  "code": 0,
  "data": {},
  "msg": "操作成功"
}
  • 成功：code = 0（HTTP 200）；无返回数据的写接口 data 为 {}；带自定义提示的接口 msg 不同（登录「登录成功」、获取自身信息「获取成功」、上传「上传成功」）
  • 业务失败（HTTP 状态码与业务码一致，data 为 null）：
{ "code": 404, "data": null, "msg": "指南不存在" }

业务错误码

code / HTTP说明
0成功（HTTP 200）
7通用失败（HTTP 200）。参数绑定失败统一走 bindFail，对外泛化提示「请求参数错误」；业务前置校验失败（如「缺少文件哈希值…」）也走此码
400参数错误（如非法状态值、缺少必要参数）
401未认证 / 认证失败（token 缺失失效；appLogin 的 appKey 不匹配）
403无权限（用户已被禁用、nxp_user_info 缺失的幽灵账号）
404资源不存在（指南/提问/媒体/机型/选项/分类等；写操作时登录用户在 Onebe 不存在）
500服务器内部错误（未知错误回退，非业务错误一律脱敏为「服务器内部错误」并记日志）
参数绑定失败（bindFail）返回 HTTP 200 + 业务码 7；BizError 的 HTTP 状态码与业务码一致（400/401/403/404/500）。

分页信封

分页列表接口的 data 统一为如下结构（下文以「分页信封」指代，仅 data.list 项结构因接口而异）：

字段类型说明
listarray当前页数据列表，项结构见各接口「响应数据」表
totalint64符合条件的总条数
pageint当前页码
pageSizeint当前页大小（请求中的 limit / pageSize 映射到此字段返回）
paginationobject冗余分页对象：page / limit / total，与上面三个字段一致
 
{
  "code": 0,
  "data": {
    "list": [],
    "total": 0,
    "page": 1,
    "pageSize": 10,
    "pagination": { "page": 1, "limit": 10, "total": 0 }
  },
  "msg": "操作成功"
}
分页参数归一化：page <= 0 取 1；limit/pageSize 缺省取 10，最大 100。列表接口统一 page / limit（用户列表、媒体列表用 page / pageSize）。

各列表默认排序

无特殊说明时，各列表接口的默认排序如下（以响应示例为准）：

列表排序
指南、提问、维修记录、媒体、设备id DESC
用户默认 nxp_user.id DESC（可 orderKey + desc 指定，见 2.1）
故障分类、问题类型、机型、维修位置id ASC
执行说明选项sort_order ASC, id ASC
维修内容position_id ASC
备件s_id DESC

1. 基础模块 /base

1.1 APP 端免密码登录 — POST /base/appLogin

POST免认证

无需认证，仅支持 application/json（不做 form 绑定）。APP 端不通过用户名/密码，而是用「用户 ID + 固定 appKey」换取一个永久有效的 APP 令牌（AppToken）。

请求参数

字段类型必填说明
userIduint是用户主键（nxp_user.id，即 JWT 载荷中的 userId）
appKeystring是固定密钥（配置 server.appTokenKey），作为「是否是 APP 端」的标志
校验逻辑：appKey 与配置常量时间比较（防时序探测），不匹配 → 401「无效的 App 凭证」（不暴露期望值）；反查 Onebe 校验用户存在且启用：用户不存在 → 404、被禁用/幽灵账号 → 403。AppToken 与 JWT 同一签名密钥，载荷 type = "app"，exp 为固定大期限（近似永久）；无自然过期概念，仅当服务端更换 appTokenKey 时全局失效（无法单独吊销某用户）。
{
  "userId": 1,
  "appKey": "<server.appTokenKey 的值>"
}

响应数据

字段类型说明
userobject登录用户（nxp_user），含 id / userId / name / createTime；不含 password
tokenstringAPP 永久令牌；后续接口放入 Authorization: Bearer <token> 即可鉴权
expire_atint恒为 0（永久有效，无过期时间）
 
{
  "code": 0,
  "data": {
    "user": { "id": 1, "userId": 1, "name": "admin", "createTime": "2026-01-01 00:00:00" },
    "token": "<appToken>",
    "expire_at": 0
  },
  "msg": "登录成功"
}
失败场景：7 userId/appKey 缺失（泛化提示「请求参数错误」）；401 appKey 不匹配「无效的 App 凭证」；403 用户已被禁用（幽灵账号或 status != 1）；404 用户不存在；500 Onebe 查询发生基础设施故障。安全注意：appKey 是 APP 令牌体系的唯一防线，生产必须使用强随机值且不要入库/提交仓库；建议配合网关限流 / IP 白名单防爆破。

15.2 静态资源 — GET /uploads/*filepath

GET免认证免超时

上传文件的静态服务（映射 server.uploadDir），用于媒体文件/现场照片直链访问；大文件传输豁免服务器级读写超时。上传接口返回的 path 即指向此处；挂载 ResourceURL() 的接口出参中会改写为完整 URL。

请求参数

路径参数 filepath：上传文件相对路径，如 /uploads/media/demo-20260906120000000.mp4。

响应数据

文件二进制内容（Content-Type 按扩展名推断）。
